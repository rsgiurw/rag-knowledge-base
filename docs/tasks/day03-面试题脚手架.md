## Q1（示范题 · 已给出完整答案，你只需做实验验证它）

**题目：`@app.post("/api/documents")` 执行时发生了什么？（装饰器角度）**

【动手】在 `app/main.py` 里加一个新接口（两行），保存：
```python
@app.get("/ping-test")
async def ping_test():
    return {"pong": True}
```
观察：① 终端立刻出现 reload 日志；② 浏览器打开 http://127.0.0.1:8000/ping-test 能看到 `{"pong": true}`。

【答案示范（读三遍，理解每句）】
> 这行装饰器在**服务启动、main.py 被加载时**执行了一次（不是每次请求时执行）。
> 它做的事是把紧跟着的函数以 **"POST + /api/documents"** 为键**登记进 FastAPI 的路由表**。
> 之后每个请求到来时，FastAPI **按"方法+路径"查路由表**，找到对应的函数执行，并把返回值转成 JSON。

【自测】关掉这个文件，口头把这三句复述出来。能说出来 Q1 就过了。

## Q2. def 路由和 async def 路由的区别？什么时候 async 反而有害？

【指认】打开 `app/main.py`，数一数：5 个接口里哪个用了 `async def`？（只有 health）它和别的接口函数体最大的区别是什么？（它体内没有任何耗时的等待）

【填空】
1. `async def` 路由跑在 FastAPI 的________上（讲义第四节的机制）；
2. 如果在 `async def` 里写了同步阻塞的调用（比如我们用的 httpx 普通请求、time.sleep），后果是________——所有其他请求都得排队等它；
3. 所以 FastAPI 对普通 `def` 路由的处理是：自动丢进________执行，不阻塞别人；
4. 我们的上传/提问接口内部要调智谱 API（同步等待几秒），所以必须写成 `def`。

【答题模板】"async def 的接口跑在事件循环上，适合体内有 await 的真异步等待；如果 async 里写了同步阻塞代码，会________。我们的接口因为内部用同步 httpx 调 API，写成 def 让 FastAPI 丢进线程池，也能并发。"

【记忆锚】服务员比喻：async = 点完单先去服务别桌，菜好再端；在 async 里干等 = 站在厨房门口堵死整个大堂。

## Q5. 请求 DELETE /api/documents/xxx 从浏览器到文档被删，经过几步？

【指认】打开三个文件，把这条链路亲眼走一遍：
- `app/static/index.html` 里的 `delDoc()` 函数（发起请求的一端）
- `app/main.py` 里的 `delete_document`（路由层）
- `app/store.py` 里的 `delete_document`（数据层）

【按顺序填空】（一步一格，全部填完数一数共几步）
1. 你在页面点"删除"按钮，confirm 弹窗确认；
2. JS 的 fetch 发出 ______ 方法、路径为 ______ 的 HTTP 请求；
3. uvicorn 收到请求报文，交给 FastAPI；
4. FastAPI 按方法+路径匹配到路由表里的 ______ 函数；
5. 函数调用 `store.delete_document(doc_id)`；
6. Qdrant 按 ______（什么条件？提示：models.FilterSelector）删除该文档的所有数据点；
7. 函数返回 `{"deleted": doc_id}`，FastAPI 把它序列化成 ______ 响应给浏览器；
8. JS 收到成功响应后重新调用 ______ 函数刷新左侧列表；
9. 你看到文档从列表里消失。

【答题模板】不用背步数（6~10 步都算对，关键是**顺序对、两端齐全**：浏览器发起 → 服务端处理 → 页面刷新）。面试官考的是你对"一次删除操作全链路"有没有整体图景。
